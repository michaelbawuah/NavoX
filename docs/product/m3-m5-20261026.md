# Milestones 3–5 engineering checkpoint — October 26, 2026

This increment builds on the already pushed M1 and M2 checkpoints. It does not
mark either earlier milestone or M3–5 accepted. The approved order remains
calendars/scheduling, memory/privacy, then the remaining student screens.

## Implemented and integrated

| Area | Behavior |
| --- | --- |
| Microsoft calendars | Separate PKCE calendar consent on the existing verified Microsoft callback; no mail scopes requested. Encrypted refresh credentials, verified account identity, scope narrowing, one-shot code exchange, session/reset/revocation checks and read-only busy-time collection. Calendar connections cannot confer Inbox authority. |
| Apple calendars | Explicit native busy-time consent and an Apple app-specific password, independently encrypted and bound to the owner and connection. Bounded CalDAV discovery/free-busy reads, credential removal on disconnect/reset and no fabricated OAuth grant. An unsupported/incomplete provider response is unavailable/partial, never free time. |
| Combined availability | All authorized Google, Microsoft and Apple connections join the existing classes, fixed commitments, routine, travel and study source inventory. Meeting searches and the separate study-plan collector both dispatch to the correct provider. Planner reads stay inside their parent transaction; no nested commit/rollback/session is introduced. Account and source revisions are checked around external reads. Unknown source/travel/routine remains unknown. |
| Two meeting choices | Purpose-aware, fresh server-derived ranking with ten minutes before and after the proposed meeting. The browser cannot submit its own source snapshot. Infeasible displaced study work is excluded. Suggestions do not create or approve an event. |
| Existing Google scheduling | Separate approved-write consent, exact review, fresh checks, durable uncertain receipts and exact version-safe Undo are preserved. Both the fresh availability check and retained native claims now reserve the incoming meeting's own buffers. |
| Memory and privacy | Explicit disclosure and an unselected 30-day/90-day/Never retention choice; encrypted text history and saved facts; source provenance; off-record RAM-only context; permitted cross-call and typed recall; corrections; searchable history; timed expiry; reviewed Forget and all-memory deletion. Recognized literal neutral declarations can create source-linked facts and dated event threads with one-time offer receipts. See the separate M4 record for the narrow learning rules and delivery limits. |
| Settings | Account-fenced controls, current-section navigation, shared dark/light tokens, visible selected appearance, sensitive-fact agreement and reviewed deletion. Voice Forget supplies a private, expiring review handoff; it cannot perform deletion. |

Memory controls require the exact browser account header, browser cookie, valid
origin for writes, and a fresh session under the owner lock. Validation errors do
not echo private submitted text. The migration refuses to discard retained memory
or active checkpoint rows during downgrade.
