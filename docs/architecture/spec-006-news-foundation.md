## Implemented in this batch

`navox.news.contracts` defines immutable, strict source, feed, rights and canonical
metadata contracts. `NewsRegistry` is an in-memory **trusted snapshot**, not a
persistent registry, an authenticated administration endpoint or a rights grant.
Unknown references, duplicate identities/revisions and cross-source rights
references are rejected. Source identity verification is not claim verification.

`navox.news.rights` checks active source/feed status, verified source identity,
explicit review reference, effective/expiry times and independent permissions.
There are no implicit rights: storage does not imply processing, summarization,
image display or redistribution. Metadata/snippet processing and display flags
extend the minimum PDF fields so those uses also require explicit review.
Attribution and the original source link are always preserved.

`navox.news.normalization` accepts already-decoded adapter metadata after its
storage check, not raw RSS/Atom/HTML. Snippets need their own storage permission.
Full text, images, rights, source IDs, retrieval times, verification labels and
actions are rejected as incoming metadata fields. Missing publication dates stay
unknown. Publication, update and event times remain distinct and timezone-aware.

Item identity is stable within a source/feed using an external ID, or otherwise
the conservatively normalized, source-supplied URL. This is replay identity,
**not** exact-duplicate precision, story clustering or independent corroboration.
URLs retain path case, query order/values and fragments; their hosts must match
an explicitly registered source host. No source URL is generated by a model.

Refreshes with `previous` preserve the original acquisition time and cannot extend
retention. A public metadata projection checks the supplied current registry,
rights binding and expiry again. Disabled sources/feeds, replaced rights bindings,
removed storage permissions, expired rows and invalid retention extensions are
blocked. A snippet no longer licensed for display is omitted. Output strings are
plain untrusted text: the future UI must escape them, never insert raw HTML.

## Boundaries that are deliberately not claimed

- No persistence, migrations, concurrent upsert protection, purge worker,
  authenticated administration, runtime wiring or source license activation is
  included yet. Expired content is denied by these functions; physical deletion
  and cache invalidation are **not implemented** by this domain batch.
- The integration must load the latest authoritative registry in the appropriate
  transaction. Supplying an old immutable snapshot cannot detect a later database
  revocation. Never accept a registry, review reference or rights profile from a
  news item, model response, or ordinary user's API request.
- Only the trusted future adapter may set `now`/`previous`. On repeated acquisition
  it must load and lock the existing identity before calling normalization;
  omitting `previous` would lose the existing retention anchor. Re-ingestion of an
  expired item needs a separately designed retention/authorization policy.
- URL validation here is syntactic, **not a complete SSRF defense**. There is no
  network transport. A later adapter must enforce pre-fetch rights, configured
  endpoints, DNS/address pinning, redirect checks, response-size/time limits,
  safe parsing and SPEC-003 credential resolution. No webpage scraping is enabled.
- Source/rights administration will require explicit operator authorization and
  reviewed current source terms. `review_reference` is only an opaque reference,
  not proof created by this code that a publisher permits any particular use.
- No AI/provider calls, email/calendar/subscription actions, X requests, live
  source reads or worker starts occur. The package does not register any runtime
  API or workflow, change settings, or modify the approved website.
- `require_summary_permission` is only a rights check. It does not qualify or
  enable `NEWS_SYNTHESIS`. Separate task-specific SPEC-005 evidence, policy,
  sensitivity, budget and rollout checks remain required before activation.
- There is no personalization state in this batch. Cross-user privacy and
  database concurrency tests belong to their real integrated implementations,
  not to the offline domain test count.

## Validation and integration

The companion delivery includes the exact local test result and environment
versions. Those are **isolated domain tests**, not the complete locked NavoX API
suite or hosted CI. No production-accuracy or security-certification claim follows
from their pass count.

The apply helper checks the pinned `origin/main`, verifies its payload hashes and
creates a separate worktree/branch. It uses the repository's unchanged `uv.lock`,
formats only the new files with the locked Ruff, and runs the existing full
`bash scripts/check-api.sh`. It does not copy the owner's `.env`, forward provider
keys or test-database overrides, start Docker, commit, push, merge or deploy.
Hosted six-job CI and integration acceptance are still separate gates.

## Next implementation batch

Persist sources, immutable rights revisions, configured feeds and canonical items
using the existing database/migration conventions. Add authenticated operator
controls, atomic replay handling that preserves first acquisition, authoritative
read-time rights checks, retention erasure and tests on real PostgreSQL. Then
integrate the first small set of sources only after their current official terms
and access mechanisms have been reviewed, with credentials in SPEC-003.

M1 is complete only when properly authorized source input becomes persisted
canonical NewsItems through the real ingestion path. M2 clustering, M3 claim
verification and later consumer UI/chat milestones must not be inferred from
this first batch.
