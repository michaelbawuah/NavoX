# Milestone 8: Chrome Extension

SPEC-001 remains authoritative. Milestone 8 exposes the existing NavoX loop in
a Chrome Manifest V3 side panel. The extension is a thin client of the same
API, PostgreSQL state, policy engine, approval engine, and Temporal workflows.
It is not a second agent architecture.

## Product boundary

The extension supports sign-in, dynamic Today state, proactive briefing state,
bounded operational questions, explicit Handle this for saved commitments,
plan progress, and review of approval-bound actions.

The extension does not read arbitrary page content, inject content scripts,
capture browsing history, inspect tabs, or execute provider actions outside the
existing NavoX API.

## Chrome permissions

The initial extension requests only `sidePanel`, `storage`, and one
build-time API origin in `host_permissions`.

There is no `tabs`, `activeTab`, `scripting`, `cookies`,
`webRequest`, or broad `<all_urls>` permission.

Chrome's official documentation defines the Manifest V3 Side Panel API,
extension storage API, and host permissions for cross-origin fetch:
- https://developer.chrome.com/docs/extensions/reference/api/sidePanel
- https://developer.chrome.com/docs/extensions/reference/api/storage
- https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions

## Authentication

Web sessions remain HttpOnly SameSite cookies. Extension sessions use the same
`user_sessions` table but are tagged `client_type=extension` and have a
separate shorter TTL.

The raw extension token is generated by the API, returned only at extension
login, stored only in `chrome.storage.local`, sent as a Bearer token by the
extension service worker, stored by NavoX only as a SHA-256 hash, and revocable
through the API. The user's password is never persisted by the extension.

## Architecture

```text
Chrome side panel
  -> message
MV3 service worker
  -> Authorization: Bearer <opaque session>
FastAPI
  -> existing tenant resolution
  -> Today / Proactive / Agent / Approval APIs
  -> PostgreSQL + Temporal
```

The side panel never talks directly to Gmail, Calendar, Drive, model providers,
or Temporal.

## Safety invariants

- no page-content capture in Milestone 8;
- no arbitrary browser/computer control;
- no new provider scopes;
- no provider credentials in extension storage;
- no raw NavoX session tokens in PostgreSQL;
- no authorization decisions in extension JavaScript;
- all entity reads and writes remain workspace/user scoped;
- extension logout revokes only an extension session;
- action risk and approval remain server-side.
